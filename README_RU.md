# TZ Checker — проверка технических заданий по корпоративным СТО

Локальное и серверное приложение: FastAPI + SQLite + браузерный интерфейс без сборки.
Проверяет ТЗ на проектирование по библиотеке СТО через любой OpenAI-совместимый
провайдер (OpenAI, корпоративный шлюз, локальная Ollama).

Версия 0.3.0. Подробности развёртывания — в [DEPLOY.md](DEPLOY.md).

## Что умеет

- **Импорт документов**: PDF с текстовым слоем, DOCX, XLSX, MD, TXT, CSV; до 20 МБ
  на файл (настраивается), без ограничения числа документов. Публичные ссылки
  Google Docs/Sheets/Drive. Дубликаты отсекаются по SHA-256.
- **Гибридный поиск по библиотеке**:
  - FTS5 (BM25) — точные словоформы;
  - индекс стемов + словарь синонимов — «дымоудаление» находит «противодымную
    вентиляцию»;
  - эмбеддинги провайдера (`/embeddings`) с локальным кэшем в SQLite;
  - объединение через Reciprocal Rank Fusion и диверсификация по источникам.
  Чат и эмбеддинги могут работать на **разных серверах**: в настройках есть
  отдельный «Base URL для эмбеддингов». Например, чат — `gpt-oss:20b-cloud`
  в Ollama Cloud, эмбеддинги — локальная `nomic-embed-text` на
  `http://127.0.0.1:11434/v1`. Если провайдер эмбеддингов недоступен,
  автоматически включаются локальные хэш-эмбеддинги (стемы + символьные
  n-граммы) — поиск работает без внешней модели и без настройки.
- **Русский язык выводов**: промпт требует, чтобы все текстовые поля были
  на русском; английский допустим только в аббревиатурах, единицах и названиях
  документов. Если модель всё же ответила по-английски, прогон получает
  предупреждение.
- **Анализ по смыслу**: промпт требует сформулировать требование ТЗ своими словами,
  построить альтернативные формулировки, сопоставить технический смысл, условия
  применимости, исключения и альтернативы. В ответе — `semantic_reasoning`,
  `severity`, `confidence`, `assumptions`, `missing_data`.
- **Программная проверка выводов**: дословные цитаты сверяются с исходным текстом,
  числа сравниваются с учётом единиц (мм↔м↔см, м²↔га, Па↔кПа↔МПа, м³/ч↔л/с,
  °C↔°F↔K и др.). Неподтверждённые цитаты и расхождения с расчётом понижаются до
  экспертной оценки.
- **Статус источника**: выводы по `PENDING_REVIEW`/`DRAFT` не могут быть зелёными
  или красными; `RETIRED` не участвует в поиске.
- **Фоновые прогоны**: запрос запуска возвращает `run_id`, прогресс опрашивается
  отдельно, пакеты сохраняются по мере готовности, сбой одного пакета даёт
  `PARTIAL`, а не потерю всего результата. Есть отмена.
- **Параллельные запросы** (1–8) с повторами и экспоненциальной задержкой на
  429/5xx/сетевых ошибках; учёт токенов.
- **Оценка до запуска**: число пакетов, ориентировочные токены и стоимость по
  заданным ценам.
- **Интерфейс**: фильтры по статусу/категории/тексту, сворачиваемые цитаты,
  массовая смена статуса СТО, шаблоны контекста, сравнение двух прогонов.
- **Область проверки**: можно ограничить анализ выбранными СТО, а не гонять всю
  библиотеку (полезно для пилотного раздела или конкретного комплекта стандартов).
- **Экспорт**: Excel с листами «Сводка», «Результаты», «Замечания» и JSON.
- **Google Sheets** (опционально): выгрузка реестра в листы `Documents`,
  `VerificationRuns`, `VerificationResults`, `Issues`, `AuditLog`.

## Запуск на Windows

1. Нужен Python 3.11+ и доступ к PyPI.
2. Распакуйте проект в папку, доступную для записи.
3. Запустите `start-local.bat` — он создаст `.venv`, установит зависимости
   (только при изменении `requirements.txt`) и откроет `http://127.0.0.1:8000`.
4. В «Настройках ИИ» укажите Base URL, модель и ключ, сохраните и проверьте
   подключение.
5. Импортируйте СТО в «Библиотеке СТО» и переведите проверенные документы в
   `ACTIVE`.
6. Загрузите ТЗ, заполните контекст (можно применить шаблон), посмотрите оценку
   стоимости и запустите проверку.

Порт можно изменить переменной `TZ_CHECKER_PORT`.

## Запуск на сервере

Кратко: `cp .env.example .env`, задать `TZ_CHECKER_TOKEN` и ключ провайдера,
`docker compose up -d --build`, опубликовать через Nginx с TLS.
Полная инструкция, systemd-вариант, бэкапы и чек-лист безопасности — в
[DEPLOY.md](DEPLOY.md).

Приложение слушает `127.0.0.1` локально и `0.0.0.0` только в контейнере.
На сервере обязателен токен: без него контейнер не стартует.

## API (кратко)

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | проверка живости (без токена) |
| GET/POST | `/api/settings` | настройки провайдера (ключ не возвращается) |
| POST | `/api/settings/test` | проверка чата и эмбеддингов |
| GET | `/api/library/standards` | документы и статистика |
| POST | `/api/library/import` | импорт файлов/ссылок |
| PATCH | `/api/library/standards` | массовое изменение статуса/редакции |
| POST | `/api/estimate` | оценка пакетов, токенов, стоимости |
| POST | `/api/analyze` | запуск фонового прогона (202 + `run_id`) |
| GET | `/api/runs/{id}/progress` | прогресс и токены |
| POST | `/api/runs/{id}/cancel` | остановка |
| GET | `/api/runs` | история |
| GET | `/api/runs/{a}/compare/{b}` | сравнение прогонов |
| GET | `/api/runs/{id}/export.xlsx` | Excel со сводкой |
| GET | `/api/runs/{id}/export.json` | JSON |
| GET/POST/DELETE | `/api/templates` | шаблоны контекста |

При заданном `TZ_CHECKER_TOKEN` все `/api/*` требуют заголовок `X-API-Token`
(или `?token=` для скачивания файлов). Запросы с чужим `Origin` отклоняются.

## Данные и безопасность

- `data/tz_checker.sqlite3` — библиотека, эмбеддинги, история, аудит.
- `data/settings.json` — настройки; на Windows ключ шифруется DPAPI и хранится
  как `api_key_enc`, старый открытый ключ мигрирует при старте.
- `data/tz-checker.log` — журнал с ротацией (2 МБ × 3 файла).
- Исходные документы на диск не сохраняются: обрабатываются в памяти.
- Извлечённый текст отправляется выбранному провайдеру — используйте только
  документы, разрешённые к передаче.
- `.env`, `data/*.json`, `data/*.sqlite3` исключены из git.

## Логирование

- **Консоль и файл**: запуск/остановка, HTTP-запросы (uvicorn access), постановка
  прогона в очередь, старт/финиш каждого прогона, ошибки пакетов, повторы
  запросов к провайдеру, ошибки эмбеддингов. Текст документов, промпты и ключи
  в журнал не пишутся.
- **Файл**: `data/tz-checker.log`, ротация при 2 МБ, хранится 3 архивных файла.
  Уровень задаётся `TZ_CHECKER_LOG_LEVEL` (`INFO` по умолчанию).
- **В интерфейсе**: «Настройки ИИ» → «Журнал приложения» → последние 200 строк
  или скачать файл.
- **API**: `GET /api/logs?lines=200` и `GET /api/logs/download` (с токеном, если он задан).
- **Аудит в SQLite**: импорт СТО, изменение статусов/редакций, завершение прогонов —
  таблица `audit_log`, просмотр через `GET /api/audit`. Ошибки и предупреждения
  каждого прогона также сохраняются в его записи.

## Ограничения

- Сканы без текстового слоя требуют OCR: установите Tesseract и
  `requirements-ocr.txt`, включите `TZ_CHECKER_OCR=1`. Без OCR такой PDF
  отклоняется с пояснением.
- Локатор — ориентир (страница/пункт/строка), а не точная ссылка PDF.
- Результаты модели — предварительные замечания для инженера, а не официальное
  заключение. Все несоответствия проверяет человек.
- Поиск по синонимам покрывает распространённые строительные термины; для узкой
  терминологии дополняйте словарь в `app/textutils.py`.
- Один worker: фоновые прогоны живут в процессе. Для масштабирования нужна
  внешняя очередь.

## Тесты

```bash
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest tests -q
```

Тесты используют изолированную временную папку данных и не затрагивают рабочую
базу и `data/settings.json`.

## Структура

```
app/
  main.py        HTTP-слой, экспорт, защита API
  runner.py      фоновые прогоны, прогресс, пул воркеров
  analyzer.py    извлечение, промпты, проверка цитат и чисел
  retrieval.py   гибридный поиск (FTS + стемы + синонимы + эмбеддинги)
  storage.py     SQLite, миграции, настройки, кэш эмбеддингов
  llm.py         клиент провайдера, повторы, JSON, embeddings
  units.py       единицы измерения
  textutils.py   нормализация, стемы, синонимы, цитаты
  secrets.py     DPAPI-шифрование ключа
  static/        index.html, app.css, app.js
deploy/          Docker entrypoint, nginx, systemd
tests/           pytest
```
